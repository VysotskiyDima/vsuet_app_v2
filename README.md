# Backend системы успеваемости и расписания ВГУИТ

Сервис сбора, обработки и предоставления данных успеваемости и расписания (coming soon...) студентов ВГУИТ. Он считывает ведомости успеваемости с официального ресурса `rating.vsuet.ru`, а затем отдает информацию по номеру зачетной книжки.


## Стек технологий

* **Язык**: Python 3.12+
* **Фреймворк**: FastAPI (с автоматической Swagger-документацией)
* **База данных**: Redis (для кеширования снимков и хранения метаданных)
* **Планировщик**: APScheduler (фоновый скрапинг успеваемости каждые 30 минут)
* **Парсинг**: httpx + BeautifulSoup4 (lxml)
* **Инструменты**: uv (для управления зависимостями), Docker, docker-compose


## Как запустить весь проект в Docker

Для сборки и запуска всего стека (FastAPI + Redis) в контейнерах:

1. Скопируйте файл конфигурации окружения:
   ```bash
   cp .env.example .env
   ```
   *(При необходимости отредактируйте параметры `PARSING_YEAR`, `PARSING_SEMESTER` или `LOG_LEVEL`)*.

2. Запустите docker-compose:
   ```bash
   docker-compose up --build
   ```

После этого:
* **API** будет доступен по адресу: `http://localhost:8000`
* **Swagger-документация**: `http://localhost:8000/docs` (все эндпоинты предзаполнены тестовым номером зачётки `247162` для быстрого ручного тестирования).
* Логирование контейнеров настроено в красивом структурированном виде с цветной подсветкой уровней логов и UUID запросов/транзакций.



## Локальная разработка и отладка (Рейтинг)

В проекте уже настроены файлы конфигурации VS Code для мгновенного старта локальной отладки.

### Инструкция по запуску:

1. Установите зависимости проекта с помощью пакетного менеджера `uv`:
   ```bash
   uv sync
   ```
2. Подготовьте локальный файл `.env` (можно использовать значения по умолчанию).
3. Откройте проект в **VS Code**.
4. Перейдите во вкладку **Run and Debug** и запустите конфигурацию **"FastAPI (local + Redis в контейнере)"**.

### Как это работает под капотом VS Code:
* При запуске конфигурации **"FastAPI (local + Redis в контейнере)"** VS Code автоматически запускает фоновую задачу `start-redis-debug`, которая создает и запускает изолированный контейнер Redis с именем **`vsuet_rating_v2-redis-DEBUG`** на стандартном порту 6379.
* После этого запускается локальное FastAPI приложение в режиме отладки (вы можете ставить брейкпоинты прямо в коде).
* При остановке отладки VS Code автоматически останавливает контейнер с помощью задачи `stop-redis-debug`.

### Уровни логирования (`LOG_LEVEL`):
В приложении реализовано два режима логирования, настраиваемых через переменную `LOG_LEVEL` в `.env`:
* **`DEV`** (по умолчанию) — соответствует уровню `INFO`. Выводит только ключевые этапы (запуск сервисов, подключение к БД, сводную информацию о стартах и финишах этапов парсинга, логи запросов). Детальные логи парсинга по каждой отдельной ведомости скрыты для предотвращения переполнения консоли.
* **`DEBUG`** — соответствует уровню `DEBUG`. Выводит полную техническую информацию, включая пошаговую обработку каждой ведомости, списки групп по факультетам, подробности HTTP-запросов и внутренние операции парсинга. Используется для детальной отладки.

## Логика работы сервиса Рейтингов

### Архитектура и структура кода
Проект построен по трехслойной архитектуре: `router → service → repository`.

```
app/
  config.py                     # настройки через BaseSettings (env)
  entities/enums.py             # VedType, Grade, маппинг URL-сегмент → тип
  parser/html_parser.py         # разбор HTML ведомости в целевые JSON-форматы
  services/parser_service.py    # ParserService: обход ASP.NET, конкурентность, ретраи
  services/student_service.py   # бизнес-логика чтения по зачётке
  repository/redis_repository.py# доступ к Redis, swap активной/фоновой БД (SCAN+MGET)
  scheduler/jobs.py             # job парсинга (раз в 30 минут)
  routers/students.py           # REST API
  main.py                       # сборка приложения + запуск планировщика
```

### Хранение данных в Redis
* **Гранулярные ключи**: Данные каждого студента по конкретной ведомости хранятся под ключом `<zach_number>:<ved_type>:<subject_name>`. Значение — самодостаточный JSON-объект.
* **Изоляция БД (Active/Background Swap)**: Чтобы читатели всегда видели целостный и стабильный снимок успеваемости во время долгого цикла парсинга (который длится до 30 минут), в Redis используются две логические базы данных:
  - **Активная БД** (из неё роутеры мгновенно считывают данные по запросам клиентов);
  - **Фоновая БД** (в неё планировщик конкурентно записывает новые спарсенные данные);
  - По успешному завершению цикла парсинга планировщик переключает указатель активной БД в служебной БД метаданных. При этом читатели начинают прозрачно видеть новые данные, а бывшая активная БД очищается и готовится под следующий цикл.

### Форматы записей успеваемости
* **Рейтинговый** (Зачёты/Экзамены с разбивкой по контрольным точкам): содержит список `control_points` (КТ1-КТ4) с оценками по видам работ (лекции, практики, лаб.) и их весами, а также итоговый балл `final_rating`.
* **Оценочный** (остальные типы ведомостей, а также Зачёты/Экзамены без КТ): содержит только поле финальной оценки `grade`. Приоритет отдается пересдачам.

### Эндпоинты API Рейтинга

Все роуты принимают номер зачётной книжки в пути и возвращают массив записей успеваемости:

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/students/{zach_number}/exists` | Проверить, существуют ли какие-либо данные по зачетке (`{"exists": bool}`) |
| GET | `/students/{zach_number}/zachet` | Ведомости типа "Зачёт" |
| GET | `/students/{zach_number}/ekzamen` | Ведомости типа "Экзамен" |
| GET | `/students/{zach_number}/vypusknaya-rabota` | Выпускные квалификационные работы |
| GET | `/students/{zach_number}/gosekzamen` | Государственные экзамены |
| GET | `/students/{zach_number}/kontrolnaya-rabota` | Контрольные работы |
| GET | `/students/{zach_number}/kursovaya-rabota` | Курсовые работы |
| GET | `/students/{zach_number}/kursovoy-proekt` | Курсовые проекты |
| GET | `/students/{zach_number}/praktika` | Отчеты по практике |
